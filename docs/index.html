A language, and the pipeline that lowers it.

NOVA is a statically-typed, compiled systems language whose compiler lowers source through a semantic pipeline to C, JavaScript, Rust and WebAssembly. The repository is NEO; the language and toolchain inside it are NOVA.

What is implemented

Semantic pipeline

A multi-pass compiler: lexer, recursive-descent parser, semantic analyser, a Semantic Intermediate Representation, a lowerer, and a backend interface.

phase 1 · complete

Four back ends

One front end, four targets. C is the reference; JavaScript, Rust and WebAssembly run an exercised subset. Arrays and closures run on all four, with growable arrays and capturing/higher-order closures in the parity corpus.

backends

Standard library

Written in NOVA itself, module by module — text, core and IO, read as ordinary source rather than as compiler magic.

stdlib

Tooling beside the compiler

A language server, a package manager and a debugger, each its own crate in the same repository.

What NOVA looks like

# NOVA Standard Library - Text Module
/// Join array of strings with separator
fn join(strings: [String], separator: String) -> String {
    if array_len(strings) == 0 {
        ""
    } else {
        let mut result = strings[0];
        let mut i = 1;
        while i < array_len(strings) {
            result = strcat(result, separator);
            result = strcat(result, strings[i]);
            i = i + 1;
        }
        result
    }
}

from stdlib/text/text.nova — the standard library is written in NOVA, not in the compiler's host language

Where it stands

Phase 1 is complete, Phase 3 is partial, and Phase 4 is in progress. The C backend is the reference. JavaScript and Rust execute arrays and closures; WebAssembly executes ints, strings, growable int arrays, structs, tuples and int closures. The suite has 184 passing tests, and CI runs test --parity over every example and parity program. Known gaps are listed in the repository README rather than hidden: WASM float struct fields, non-int WASM closure signatures, LSP references, and DWARF debugging. Claims on this page come from the repository's README and development plan, where the development plan is authoritative.
